# Contribuindo

Aceitamos melhorias voltadas à defesa, privacidade, hardening, detecção e resposta a incidentes.

Não envie código para exploração de terceiros, coleta de credenciais, persistência, evasão, malware ou varredura de alvos não autorizados. Toda demonstração deve usar dados fictícios, localhost ou um laboratório sob controle do autor.

Inclua objetivo, pré-requisitos, impacto esperado, limitações e como desfazer a alteração. Issues e pull requests devem manter linguagem técnica, clara e responsável.
